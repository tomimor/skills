# The technical checklist

The pass bar for every audit item, with the facts and limits behind it.
Sources: Google Search Central, web.dev, Bing/IndexNow docs, and vendor
crawler documentation. AI-specific policy lives in [geo.md](geo.md).

## Indexability fundamentals

Google's minimum bar for a page to be indexable is deliberately small:
crawler not blocked, page returns 200 with indexable text content, no
noindex. Everything else is optimization on top.

| Item | Pass bar | Notes |
|---|---|---|
| Status codes | Indexable pages return 200; gone pages return 404/410 | Only 2xx pages (in practice 200) are indexed. Soft 404s (junk paths returning 200) waste crawl budget and can index garbage |
| noindex vs robots.txt | Use `noindex` (meta or `X-Robots-Tag`) to keep pages out of the index; use robots.txt only to control crawling | robots.txt does NOT de-index: a blocked URL can still appear in results (crawler never sees the noindex). `noindex` inside robots.txt is unsupported |
| Page weight | Main content well inside the first ~15 MB | Googlebot fetches only the first 15 MB of a file; content beyond it is ignored |
| Access | Public, no login wall, crawler UAs not blocked at WAF/CDN | Check bot-protection defaults (Cloudflare etc.) aren't challenging Googlebot/Bingbot/AI fetchers |
| Mobile | Responsive; content parity mobile vs desktop | Google indexes mobile-first (smartphone crawler) |

No technical setup *guarantees* crawling or indexing — treat the
checklist as necessary, not sufficient. New sites are discovered through
links; manual submission isn't required, but a sitemap + Search Console
speeds it up.

## robots.txt

| Item | Pass bar |
|---|---|
| Location & status | `/robots.txt` at the host root, returns 200 (or 404 if intentionally absent — 404 means "all allowed") |
| Availability | Never 5xx: Google initially treats an erroring robots.txt as full-disallow (~12h crawl stop), falls back to a cached copy for up to ~30 days, and only after that may assume no restrictions or throttle crawling |
| No accidental blocks | No `Disallow: /` for `User-agent: *` left over from staging; assets (JS/CSS) not disallowed — Google must render pages |
| Sitemap directive | `Sitemap: <absolute-url>` line present |
| AI crawler groups | Explicit per-bot groups reflecting a *decided* policy (see [geo.md](geo.md)); default-allow is a valid decision |

## XML sitemap

Sitemaps are optional per Google — a hint, not a guarantee — but Google
itself flags "your site is new and has few external links" as exactly
the case where a sitemap helps, and AI crawlers lack Google's mature
discovery infrastructure. For a fresh site, a generated sitemap +
Search Console submission is the cheapest discovery accelerator there is.

| Item | Pass bar |
|---|---|
| Generation | Generated by the framework at build/request time, not hand-maintained |
| Limits | ≤ 50,000 URLs and ≤ 50 MB uncompressed per file; use a sitemap index above that |
| URL quality | Absolute URLs, canonical form only (final host/protocol/slash, no redirects, no noindexed or 4xx URLs, no URL parameters) |
| lastmod | W3C datetime, and honest — only bump when content meaningfully changes; engines learn to distrust always-fresh lastmod |
| Discovery | Referenced in robots.txt and submitted in Search Console + Bing Webmaster Tools |

## URL structure & canonicalization

| Item | Pass bar |
|---|---|
| One host | www or apex — one serves 200, the other 301/308s to it |
| One protocol | http → https, 301/308, one hop |
| One slash policy | `/path` vs `/path/` — one form serves 200, the other redirects; sitemap and canonicals use the winning form |
| Redirect chains | Any variant reaches the final URL in ≤ 1 hop |
| Readability | Lowercase, hyphen-separated words; no session IDs or gratuitous parameters |
| rel=canonical | Every indexable page: exactly one, absolute, self-referencing (or deliberately pointing at the preferred duplicate) |

Canonical facts: the tag is a **strong hint**, not a directive — Google
can override it; sitemap membership is a weak hint. Duplicate content is
not a penalty, just wasted crawl and diluted signals, and Google
canonicalizes automatically if you don't. Directory structure barely
matters for ranking; per-directory crawl scheduling only kicks in at
thousands-of-pages scale.

## Rendering & JavaScript

The highest-leverage section for GEO: mainstream AI crawlers fetch but
don't execute JavaScript (evidence and exceptions in [geo.md](geo.md)).
Google itself renders JS (three-phase crawl → render → index, rendering
may be delayed) but recommends SSR/SSG because "not all bots can execute
JavaScript".

| Item | Pass bar |
|---|---|
| Content in raw HTML | Main content present in the HTTP response body without JS execution (SSG/SSR/prerender) |
| Dynamic rendering | Not used — Google deprecated UA-sniffing prerender layers. Prerendering the same HTML for everyone is fine and is not cloaking |
| Links | Real `<a href="...">` elements — crawlers don't follow `onClick` navigation |
| Routing | History API, not `#/` fragment routing — fragments aren't crawled as separate URLs |
| SPA error states | Unknown routes end in a real 404 (JS redirect to a server-404 URL, or JS-injected noindex) |
| JS-modified meta | Don't rely on JS to *remove* a server-sent noindex (render may be skipped); JS-injected canonicals/noindex are picked up but server HTML is safer |

## Per-page metadata

| Item | Pass bar |
|---|---|
| `<title>` | Unique per page, ≲ 60 chars, brand last |
| meta description | 50–160 chars; engines may rewrite, but it feeds snippets and AI previews |
| meta robots / X-Robots-Tag | No accidental `noindex`/`none` in production |
| `<html lang>` | Set correctly |
| viewport | `width=device-width, initial-scale=1` |
| charset | `<meta charset="utf-8">` first in head |
| Open Graph | `og:title` + absolute `og:image` at minimum (full treatment: `share-ready` skill) |
| favicon | Present — shown in SERPs |
| meta keywords | **Do not add** — unused by Google; folklore |

## Structured data (JSON-LD)

Use JSON-LD (Google's preferred format). Validate with the Rich Results
Test / schema.org validator. Verified caveat: an Ahrefs causal study
found adding schema does **not** increase AI citations — implement it for
its real benefits (SERP rich results, entity/knowledge-graph
recognition), not as a GEO lever.

| Page type | Schema |
|---|---|
| Every page (site-wide) | `Organization` (logo, sameAs) on home; `WebSite` on home |
| Content pages | `Article`/`BlogPosting` + `BreadcrumbList` |
| Product pages | `Product` + `Offer` (price, availability) |
| FAQ content | `FAQPage` — rich-result eligibility restricted to authoritative gov/health sites, still useful as entity data. `HowTo` rich results are fully deprecated by Google — don't add HowTo for SERP reasons |
| Local business | `LocalBusiness` (address, hours, geo) |

Only mark up content that's visible on the page; invented markup risks
manual actions.

## Internationalization (only if multi-locale)

| Item | Pass bar |
|---|---|
| hreflang | On every localized page: full alternate set, **including a self-reference**, bidirectional across all locales |
| x-default | Present, pointing at the language-selector or default locale |
| Codes | ISO 639-1 language + optional ISO 3166-1 region (`en`, `en-GB`, `pt-BR`) — `en-UK` and `english` are invalid |
| Placement | Pick one: head `<link>`, HTTP headers, or sitemap — don't mix |

## Performance / Core Web Vitals

Field data at the **75th percentile**, mobile and desktop separately.
Passing = all three simultaneously:

| Metric | Good |
|---|---|
| LCP | ≤ 2.5 s |
| INP (replaced FID) | ≤ 200 ms |
| CLS | ≤ 0.1 |

Technical-setup levers (not exhaustive): compress HTML (brotli/gzip);
long-lived `Cache-Control` + hashed filenames on static assets; images
with explicit dimensions, modern formats, `loading="lazy"` below the
fold; `font-display: swap` + preload for critical fonts; HTTP/2 or HTTP/3;
CDN in front of SSR origins (SSG + CDN gives the best TTFB); minimal
render-blocking scripts. Lab-check with Lighthouse; field data arrives in
CrUX/GSC after ~28 days of traffic.

## Security & headers

| Item | Pass bar |
|---|---|
| HTTPS | Everywhere, valid cert, no mixed content |
| HSTS | `Strict-Transport-Security` with sensible max-age |
| X-Content-Type-Options | `nosniff` |
| Compression | gzip or brotli on text responses |

## Verification & monitoring

| Step | Detail |
|---|---|
| Google Search Console | **Domain property** needs DNS TXT/CNAME verification; URL-prefix properties also accept HTML file, meta tag, GA, or GTM. Data collection starts when the property is added — add early. Tokens are re-checked periodically; leave them in place |
| Bing Webmaster Tools | Import verified properties from GSC (no separate verification). Bing's index covers Bing + DuckDuckGo and historically backed ChatGPT search; OpenAI also indexes directly via OAI-SearchBot |
| Sitemap submission | Submit in both consoles; watch Page-indexing report for exclusion reasons |
| IndexNow | Key file at root + ping on publish. Used by Bing/Yandex/Seznam/Naver, **not Google**. Worth it for frequently-updated sites; skip for small static ones |
| CrUX / CWV | Monitor the Core Web Vitals report in GSC once field data exists |
