skills

41 agent skills I use daily across Cursor and Claude Code.

Install View on GitHub

Problems it solves

Skill drift across tools

Cursor and Claude Code each want their own skills folder, so you end up copy-pasting and they fall out of sync. skills makes ~/.cursor/skills and ~/.claude/skills symlinks to a single skills/ directory, so both agents read from the same source.

Mixing your own workflows with third-party skill packs

Vendor packs like Impeccable live in their own repos and update on their own cadence. They're tracked here as git submodules under vendor/ and exposed through symlinks in skills/, so one command updates everything: ./install.sh --update-vendor.

No central place to collect, curate, and author skills

Good skills come from everywhere: ones you refined in chat, vendor packs you found on GitHub, forks of someone else's idea, half-finished drafts. Without a hub they scatter into dotfiles, gists, and Slack messages, and you lose track of which ones you actually use. This repo is the hub. Drop your own skills in as folders under skills/, pull in vendor packs as submodules under vendor/, prune what you've outgrown, and replicate the whole set to a new machine with one install script. Authoring, updating, curating, and syncing all run through the same place, version-controlled, on your own cadence.

How it works

Both Cursor and Claude Code discover skills from a single directory. Own skills live as regular folders under skills/. Vendor skills are symlinks pointing into git submodules under vendor/.

Skills

GitHub & Git

pr-dashboard own

Status overview of all your open PRs: title, reviews, CI, open comments, and a recommended next step per PR.

miguel-review own

Opinionated diff review biased toward minimal diffs and deletions, with zero tolerance for dead code or premature abstractions.

review-pr own

Senior-level review of a teammate's PR: a short list of high-signal comments to paste into GitHub. Drops nitpicks; never auto-posts.

verify-pr own

Three-phase PR verification: code review (via miguel-review), test plan with gap analysis, and upstream-assumption validation.

gh-pr-comment-assistant own

Fetch the latest PR review comments, group and prioritize them, summarize each reviewer's ask, and plan the fixes.

gh-pr-description-updater own

Read or rewrite a PR description following the repo's template. Enforces brevity and template compliance.

gh-pr-list own

A short, copy-paste Slack message of your open PRs, split into “Ready for review” and “Drafts.”

gh-issue-creator own

Create a well-labeled GitHub issue from a bug, feature, or tech-debt template. Fetches labels dynamically.

gh-issue-triage own

Score open, unassigned issues against an AI-readiness rubric and return the top 3 with a ready-to-paste kickoff prompt each.

git-worktrees own

Give every agent conversation its own branch in its own directory, so parallel chats stop clobbering each other.

update-branch own

Pull the latest from main and merge it into the current working branch.

save-and-archive own

Land a worktree onto main in solo projects: auto-commit, sync, resolve conflicts, fast-forward, push, and remove the worktree.

A gate that blocks “done” claims without fresh, executed proof. Adapted from obra/superpowers.

Bootstrap a full AGENTS.md + .agents/ guide system using progressive disclosure.

Frontend & design

ui-review own

Parallel frontend review across typography, layout, accessibility, responsiveness, copy, and polish. Prioritized small fixes, never rewrites. Polish pass includes a CSS-details checklist adapted from make-interfaces-feel-better.

grid-review own

Read-only audit of a page’s layout grid: column adherence, baseline rhythm, optical alignment, then a critique. Adapted from hyperagent-public-skills.

impeccable vendor

Design, critique, polish, and animate frontend interfaces. 24 internal commands (shape, audit, critique, animate, polish, live, generate, …; craft is now a deprecated alias). Its impeccable context launcher downloads a self-contained binary on first run, no Node required. v4.3.1, from pbakaus/impeccable.

review-animations vendor

Review animation and motion code against a high craft bar: justified motion, responsive easing, sub-300ms UI, correct transform-origin, interruptibility, GPU-only props, reduced-motion. Emits a Before/After/Why table and a Block/Approve verdict. From emilkowalski/skill.

share-ready own

Audit + fully configure how a site looks when shared (Open Graph, Twitter/X cards, per-platform quirks) and in the browser (title, favicons, theme-color, web manifest). Detects the framework, infers brand values from the repo, generates missing assets (favicon set, 1200×630 og:image), and verifies everything end-to-end with a local script.

seo-geo-audit own

Technical SEO/GEO audit + fixes for a site: crawlability, sitemaps, robots.txt + AI crawler policy (GPTBot, ClaudeBot, PerplexityBot…), canonicals, structured data, rendering strategy, hreflang, CWV basics, and search-engine verification. Ships a dependency-free live-site auditor script and a verified-vs-folklore GEO reference.

emil-design-eng vendor

Build-time companion to review-animations: Emil Kowalski’s design-engineering playbook for crafting interfaces that feel right — animation decision framework, component building, transforms, gestures, performance, a11y. From emilkowalski/skill.

animation-vocabulary vendor

Reverse-lookup glossary that turns a vague description of a motion effect into its exact term (“the bouncy thing when a popover opens” → Pop in; “the iOS rubber-band scroll” → Rubber-banding). For naming an effect, not designing or building one. From emilkowalski/skill.

apple-design vendor

Apple’s approach to interface design and fluid, physical motion, translated for the web: gesture-driven UI, spring animations, drag/swipe/sheet interactions, momentum and interruptible transitions, translucent materials and depth, typography, reduced-motion, and the design foundations behind Apple-style interfaces. From emilkowalski/skill.

Loops

Skills that run in iterations with explicit terminal states, designed to drive a repo toward a verified goal (or to re-run on a schedule) instead of doing a one-shot task.

loop-cve-audit own

Iterative dependency-CVE remediation: scan with advisory tooling, prove reachability with call-path evidence, fix the highest-risk finding with the smallest credible change, re-verify, repeat. Ends CLEAN, ASSESSED (evidence + approved risk decisions), or BLOCKED.

loop-react-doctor own

Drive every React app to a react-doctor 100/100 (latest at run start, pinned within the run), one root cause per iteration with tiered verification. Never silences findings; ends PERFECT, JUSTIFIED (user-approved exceptions), STALLED, or BLOCKED.

Setup

Install all skills

curl -fsSL https://raw.githubusercontent.com/tomimor/skills/main/install.sh | bash -s -- --all

Install a single skill

curl -fsSL https://raw.githubusercontent.com/tomimor/skills/main/install.sh | bash -s -- --skill pr-dashboard

Update vendor skills

./install.sh --update-vendor

Install flags

FlagDescription
--allInstall all skills (non-interactive)
--skill <name>Install a single skill by name
--target <dir>Override the install directory
--forceOverwrite existing skills without confirming
--symlinkSymlink skills into the target instead of copying (live edits)
--selfWire this repo into your own ~/.cursor and ~/.claude with edit-once symlinks
--checkValidate skill frontmatter and SKILLS-array sync, then exit (used in CI)
--update-vendorUpdate vendor submodules to their latest versions

Where skills live

PlatformPath

Most GitHub-related skills need the GitHub CLI (gh). writing-voice, writing-google-style, teach, and remotion-best-practices have no extra requirements (writing-google-style ships a scanner script that needs only bash and awk). impeccable downloads its self-contained launcher binary once on first run.
